# Quickstart

This gets you a real quote off the live network, then explains the decisions in
the code that are not obvious. Everything here comes from running the file below.

## Run it

From a checkout, after [installing and building](/developers/install):

```sh
node apps/docs/examples/quote.ts GBD4SMJWOYPPTVSRUK7J5M3JHHOOIEUMWYGQOLHVHUDL4ZN2ESE3BJYA 25 ethereum-sepolia
```

Three rails are asked at once. On the test network, CCTP answers with a route and
the other two decline, each with a reason you can read: LayerZero's registry
carries no testnet token to route, and Axelar either declines or does not answer
inside the racing budget. Neither is an exception or a silent omission; both are
values in `RouteSet.rejected` with a reason you can branch on and a sentence you
can show. [Routes and rejections](/developers/concepts/routes) covers the model.

## Four decisions in there that are not obvious

### The network is configuration, never a code path

`createNetworkConfig` is called with an explicit `id`. There is no testnet mode
in these packages and no default network, because a product that moves money must
never be ambiguous about which one it is on.

Mainnet needs one more decision from you. The Stellar Development Foundation runs
no public mainnet RPC, so `PUBLIC_TESTNET_RPC_URL` has no mainnet twin to swap in.
`PUBLIC_MAINNET_RPC_URLS` carries endpoints ordered by latency, and you point at
your own provider in production.

### `RpcClient` refuses stale answers, and that is why it retries

Stellar's public testnet endpoint is load balanced across nodes that are not at
the same point in the chain's history. Ask twice and you can be told an account
exists, then that it does not.

`RpcClient` keeps a high-water mark of the highest ledger it has seen, rejects any
answer from behind it, and retries with backoff. A call that takes a second longer
than you expected is the guard working. When it gives up it throws a `MavnaError`
with `retryable: true`, which is a different thing from the destination being
unusable.

### An asset is a chain plus an identifier, never a symbol

```ts
const to: Asset = {
  chainId: "stellar-testnet",
  id: `USDC:${CCTP_CONTRACTS[NETWORK].usdcIssuer}`,
  symbol: "USDC",
  decimals: 7,
  curatedBy: "Circle",
};
```

Anyone can issue a Stellar asset with the code `USDC`. Identity is the code plus
the issuer, so `id` carries both; on an EVM chain it is the token contract.
`symbol` is for display, and nothing decides anything from it. Note the decimals:
six on the EVM side, seven on Stellar. The adapter converts between them in
`BigInt`. [Assets and amounts](/developers/concepts/model) is the full rule set.

### Amounts are integer strings, in base units, everywhere

`sends.baseUnits` is `"25000000"`, not `25`. Floating point on money is a defect,
and 7-decimal Stellar amounts exceed what a double represents exactly. `amountOf`
from `@mavna/core` builds one and throws on anything that is not a non-negative
integer.

## Signing is yours

Quoting and building are separate steps, and `buildTransactions` neither signs
nor submits: what comes back is what to send, and the wallet is the only thing
that holds a key. The number of signatures a route needs can differ from the
number of transactions it returns, because some transactions are skippable.
[Signing](/developers/concepts/signing) walks through the counting, the skippable
approvals, and the Stellar-side signatures the sponsor flow collects.
