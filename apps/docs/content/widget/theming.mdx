# Theming

The widget is styled by CSS custom properties, all declared on its `.mv-root`. You
change how it looks by setting those tokens, and you have two ways to do it.

## Through the config

The `theme` field applies overrides as inline custom properties on the root, which
beat any stylesheet, so this is the way that always wins:

```tsx
<MavnaWidget
  config={{
    integrator: "your-product",
    theme: {
      tokens: { "--mv-surface": "#101014", "--mv-ink": "#f4f4f5" },
      font: "inherit",
      radius: "12px",
    },
  }}
/>
```

`theme` carries `tokens` (any custom property), `font`, `fontMono`, `radius`, and
`radiusLg`.

## Through CSS

You can also override tokens in your own stylesheet. The widget declares them on
`.mv-root`, so a plain `.mv-root` rule of yours ties on specificity and which one
wins depends on the order your bundler emits the stylesheets. Doubling the class
outranks it outright:

```css
.mv-root.mv-root {
  --mv-surface: #101014;
  --mv-ink: #f4f4f5;
}
```

Setting the tokens on an ancestor does not work: custom properties inherit, but the
widget redeclares them on `.mv-root`, and a declaration on the element beats a value
inherited into it.

## Light, dark, and system

`appearance` chooses the theme, and there are three states:

```tsx
appearance: "system"   // follows the OS preference. The default.
appearance: "light"
appearance: "dark"     // wins over the OS in both directions.
```

The widget writes the choice to a `data-mv-theme` attribute on its root, and leaving
it on `system` follows the reader's machine, which is the right default inside
someone else's page: a light host on a dark OS is a real and common case, so an
explicit instruction has to win rather than merely be considered. If you retheme,
set your tokens in both the light and the dark case, or your dark theme is a light
theme with two colours changed.

## The one colour to leave alone

`--mv-signal` is the only chromatic token in the widget, and it means something has
gone wrong. It is deliberately not used for "approve this in your wallet", a normal
thing to be asked. If you retheme it to your brand colour, every error state becomes
a button.

## What you cannot restyle

Class names and the DOM structure are not API. They are prefixed `mv-` so they
cannot collide with your page, and reaching into them with descendant selectors will
break on a patch release. If a token you need does not exist, that is a gap in the
list rather than an invitation to select the internals.
