The widget has no theme object, no CSS-in-JS, and no build-tool requirement. It
has custom properties, all of them declared on `.mv-root`, and overriding one is
the whole mechanism.

```css
/* Doubled so it outranks the widget's own .mv-root rule whatever order your
   bundler emits the two stylesheets in. */
.mv-root.mv-root {
  --mv-surface: #101014;
  --mv-ink: #f4f4f5;
  --mv-radius: 12px;
  --mv-font: inherit;
}
```

The [playground](/playground/) writes this block for you, against a live quote.


### Why the class is written twice

The widget declares every token in a `.mv-root` rule of its own. A plain
`.mv-root` rule of yours ties with it on specificity, and a tie is settled by
which stylesheet the browser saw last, which is a question about your bundler
rather than about your CSS. Sometimes you win, and when you lose there is nothing
in the output to look at.

`.mv-root.mv-root` outranks it outright. Scoping under a container you own works
too, and is nicer if you have one:

```css
.checkout-panel .mv-root {
  --mv-surface: #101014;
}
```

Setting the tokens on an ancestor does **not** work, and this is the failure that
looks like the widget ignoring you. Custom properties inherit, but the widget
redeclares all of them on `.mv-root`, and a declaration on the element beats a
value inherited into it.

## What each group is for

**Surfaces and ink.** `--mv-ground` is transparent on purpose: the widget is a
guest and does not paint a background over whatever it was placed on.
`--mv-surface` is the panel itself, `--mv-ink` the text, `--mv-muted` secondary
text, and the two rule values are borders and dividers.

**`--mv-signal` is the only chromatic value in the package** and it means
something has gone wrong. It is deliberately not used for "approve this in your
wallet", which is a normal thing to be asked and would be misrepresented by an
alarm colour. If you retheme it to your brand colour, you have made every error
state look like a button.

**Spacing** is a seven-step scale, `--mv-1` through `--mv-7`. It is one scale, and
components use steps from it rather than arbitrary values, so changing a step
changes everything that uses it.

**Type.** `--mv-font` defaults to a system stack rather than `inherit`, which
looks like the wrong choice until you meet a host page that sets no face at all
and lands the widget in the browser's default serif. Set it to `inherit` to adopt
your page's typeface, or name one. Do not point it at a webfont you have not
already loaded.

**Geometry.** `--mv-radius` and `--mv-radius-lg`, both in pixels. Every dimension
in the stylesheet is in pixels rather than `rem`, because `rem` resolves against
the host page's root font size: a page that scales `html` would otherwise rescale
the widget's geometry while the box it was given stays exactly the same size.

**Motion.** Two easings and two durations, expressed in CSS. The widget ships no
animation library, because it runs in your page and a motion runtime is your
users' bytes. `--mv-swell` is symmetric, for anything that breathes rather than
arrives.

**`--mv-hull`** is the width of the draft scale's hull. The graduation marks are
positioned from it, so they stay attached if you change it.

## Light and dark

Three states, and the widget handles all three without being told which:

```css
/* Follows the system preference. */
.mv-root { }

/* Wins over the system preference, in both directions. */
.mv-root[data-mv-theme="light"] { }
.mv-root[data-mv-theme="dark"] { }
```

Pass `theme="light"` or `theme="dark"` to set the attribute from React. Leaving
it undefined follows the machine, which is the right default in someone else's
page. A light host running a dark OS is a real and common case, which is why an
explicit instruction has to win rather than merely being considered.

If you retheme, redefine your tokens in all the places the widget does, or your
dark theme will be a light theme with two colours changed.

## What you cannot restyle

Selectors, class names, and the DOM structure are not API. They are prefixed
`mv-` so they cannot collide with your page, and reaching into them with
descendant selectors will break on a patch release.

If a token you need does not exist, that is a gap in the token list rather than
an invitation to write `.mv-root .mv-panel > div:nth-child(2)`.
