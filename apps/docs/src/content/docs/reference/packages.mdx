Nine packages, three of them rails. Each table is read out of that package's
`src/index.ts` when this site is built, so a name here is a name that exists.

Every package is ESM only, ships its own types, and is pinned exactly rather than
by range.

## `@mavna/core`

The type model and nothing else. Every other package depends on it and it depends
on none of them. Start here if you are implementing a
[`BridgeAdapter`](/reference/bridge-adapter/).

<Core />

## `@mavna/routing`

Racing adapters and turning a destination's state into a sequence of steps.
`planTransfer` is where "this account does not exist yet" becomes "there is a
preparation step before the bridge", and `signatureCount` is where the number the
user is promised comes from.

<Routing />

## `@mavna/stellar`

Reading Stellar, and the two transactions sponsorship needs. `RpcClient` is the
freshness guard: it refuses answers from a node behind the highest ledger it has
seen, because the public endpoint is load balanced across nodes at different
heights and will otherwise contradict itself between two calls.

`classifyAddress` and `inspectDestination` answer what a destination actually is
and what it actually requires, rather than inferring it from the shape of the
string. `buildPreparation` and `buildSettlement` return unsigned transactions;
neither signs.

<Stellar />

## `@mavna/status`

One state machine for a transfer in flight, and resumption from whatever the user
still has. `applyUpdate` refuses to walk a terminal step backwards.
`RESUMPTION_DOES_NOT_REQUIRE_A_WALLET` is an assertion with a name, which is the
point: resuming needs a hash or an address, never a session or an account.

<Status />

## `@mavna/swap`

Swap providers on Stellar, behind one interface, with slippage applied from the
user's chosen bound rather than a default.

<Swap />

## `@mavna/adapter-cctp`

Circle's CCTP as a rail. Everything specific to Circle is in this package and
nothing outside it mentions Circle at all.

The chain registry in here was generated by probing the chains rather than
transcribed from documentation: for each one, the sweep confirmed there is code
at the messenger address, asked that contract for its local minter, asked the
minter which token is local USDC, and asked the token whether it agrees it is
USDC with six decimals. A chain that could not answer all four is absent rather
than guessed at.

The surface is large because the encoding details are exported rather than
hidden. `buildForwarderHookData`, `contractAddressToBytes32` and
`classifyForwardRecipient` are the paths where a wrong value destroys funds with
no recovery, and they are exported so they can be tested and audited directly.

<Cctp />

## `@mavna/adapter-axelar`

Axelar as a rail, reaching Stellar through its Interchain Token Service. A
validator set attesting rather than an issuer burning and minting.

**Nothing about Axelar's deployment is a constant in here.** Not the chain names,
not the contract addresses, not the token identifiers: every one is resolved at
runtime. That is not caution for its own sake. Axelar registers Stellar under a
versioned chain identifier that changes when they redeploy, old identifiers are
never retired, and a stale name routes into a graveyard rather than erroring. The
fee estimator returns zero for an unknown name, which would underpay and strand a
transfer. `assertChainAgrees` and `assertFeeIsPlausible` exist because both
failures are silent.

<Axelar />

## `@mavna/adapter-layerzero`

LayerZero OFTs, and on mainnet the only route to native USDT on Stellar.

`ROUTED_SYMBOLS` is empty for testnet, deliberately. LayerZero's OFT registry
carries no testnet chains on any chain, so there is nothing to resolve a symbol
against, and every OFT actually peered to Stellar testnet is a private deployment
whose token nobody else can obtain. Naming a default there would be quoting a
route no user can take. Pass your own through `LayerZeroAdapterOptions.ofts`.

`assertDvnStackIsSound` is the one to read before trusting a route: it checks the
verifier stack rather than assuming the defaults are configured.

<LayerZero />
